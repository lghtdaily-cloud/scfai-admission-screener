# 申请人筛选与一键联系小程序

基于需求文档，为「四川美术学院实验艺术学院 · 艺术与文旅产业融合创新设计微专业」招募打造的**双端微信小程序 + 微信云开发**应用，覆盖「收材料 → 筛选 → 联系」全流程自动化。

- **学生端**：链接 / 小程序码进入，在线填写报名表（字段与《报名申请表》一一对应），上传简历 / 作品集 / 成绩单 / 个人陈述，查看提交状态。
- **主办方端**：上传招募信息并自动解析筛选标准（三张清单 + 最少录取人数）、候选人库管理、五步流水线智能筛选（含录取率兜底）、心仪候选者标记、录取文案编辑与一键联系（QQ 邮箱 / 电话 / 微信）、导出 5 个 xlsx 交付物。

智能能力默认走**确定性规则引擎**，无需任何密钥即可完整跑通；在 `config/env.js`（或云数据库 `config` 集合）配置 OpenAI 兼容的 LLM Key 后，「招募信息解析 / 作品集解析 / 智能筛选」自动升级为调用大模型。

## 二、环境准备

1. 安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）。
2. 准备一个**小程序 AppID**（在 mp.weixin.qq.com 注册；测试可用「测试号」，但云开发需真实 AppID）。
3. 打开项目：开发者工具 → 导入项目 → 选择本目录 `screener-miniprogram` → 填入 AppID。
4. 开通云开发：点击工具栏「云开发」→ 创建环境 → 记下**环境 ID**。

---

## 三、部署步骤（关键）

1. **配置云环境 ID**：打开 `config/env.js`，把 `CLOUD_ENV` 改为你在步骤 4 创建的环境 ID。
2. **部署云函数**（每个都需操作）：在 `cloudfunctions/` 下，对以下每个文件夹**右键 → 上传并部署：云端安装依赖（不上传 node_modules）**：
   - `submitApply`、`parseRecruit`、`parseFormTpl`、`parsePortfolio`、`importMail`、`screenPipeline`、`genContact`、`exportXlsx`
   - **`notifyNewApply`**（新报名订阅消息推送，见步骤 5）
   - `exportXlsx` 依赖 `exceljs`、`importMail` 依赖 `adm-zip`，云端安装依赖时会自动安装；若失败可先在本地该函数目录 `npm install` 再上传。
3. **开通数据库集合**：云开发控制台 → 数据库 → 新建集合：`candidates`、`recruit`、`screenResult`、`config`、`notify`（权限设为「所有用户可读，仅创建者可读写」或「自定义」，便于测试可先设为所有用户可读写）。
4. 编译运行即可。

5. **（可选但强烈推荐）开启「有新的报名」微信提醒**：
   1. 小程序后台 `mp.weixin.qq.com` → 功能 → 订阅消息 → 公用模板库，选用「新申请 / 报名提醒」类模板，记下**模板 ID**；
   2. 把模板 ID 同时填到 `config/env.js` 的 `SUBSCRIBE.TEMPLATE_ID` 与 `cloudfunctions/notifyNewApply/env.js` 的 `SUBSCRIBE_TEMPLATE_ID`；
   3. **照你申请到的模板字段名，改 `cloudfunctions/notifyNewApply/index.js` 里 `data` 的 `thing1/thing2/time3/thing4`**（微信小程序规定必须逐字段对应，名字对不上会推送失败）；
   4. 部署 `notifyNewApply` 云函数；主办方在小程序首页点「🔔 开启 / 续期提醒」授权即可。
   5. 之后学生每次提交，`submitApply` 会自动链式调用它推送，主办方微信实时收到通知。
   > 说明：订阅消息由**接收方**授权，所以是**主办方**点授权，不是学生。一次性订阅每授权一次可推一条，可多次点击续期累积。

## 四、可选：启用大模型智能解析

默认规则引擎即可完整使用。如需更智能的招募信息解析 / 作品集解析，在云数据库 `config` 集合新建文档 `_id: llm`，内容：

```json
{
  "ENABLED": true,
  "BASE_URL": "https://api.openai.com/v1",
  "API_KEY": "你的密钥",
  "MODEL": "gpt-4o-mini"
}
```

或在 `config/env.js` 的 `LLM` 字段直接填写后重新部署 `parseRecruit` / `screenPipeline`。未配置时自动回退规则引擎。

## 五、自测流程（检测运行）

### 主办方端（tab「主办方」）
1. **上传招募信息**：进入「上传招募信息」→ 点「载入川美样例」→「解析筛选标准」→ 得到硬条件 / 加分项 / 排除项 + 最少录取人数 25 →「保存招募配置」。（也可粘贴自己的招生简章文本。）
2. **收集材料**：学生端提交，或主办方后续通过邮件导入（本期以小程序直传为主）。
2.5 **作品集解析**：进入「作品集解析」→「解析全部作品集」，输出类别 / 风格 / 优势 / 短板四维度概述并写入候选人信息总表。未配置 LLM 时走规则引擎（关键词词典 + 原文证据），配置后自动升级为大模型。
3. **智能筛选**：进入「智能筛选」→「运行筛选」。查看总数 / 推荐 / 待定 / 淘汰，以及触发的兜底放宽记录与三档名单（筛选前会自动为未解析的候选人补跑作品集解析）。
4. **心仪候选者**：在候选人详情点「标记心仪」，于「心仪候选者」独立成组、优先约面，可单独导出。
5. **一键联系**：候选人详情 →「一键联系」→ 编辑录取文案（支持 `{姓名}` `{活动名称}` 变量）→ QQ 邮箱（复制收件人 / 全文 + 去写信）、电话（原生拨号）、微信（复制微信号）。
6. **导出交付物**：筛选页「导出交付物 (xlsx)」生成 材料清单 / 候选人信息总表 / 初筛结果 / 面试准备表 / 心仪候选者名单；心仪页可单独导出心仪名单。

### 学生端（tab「学生报名」）
1. 先看「招生介绍」（内嵌公众号文章链接）。
2. 填表：基本信息 + 专业能力技能 / 提升方向 / 承担工作（多选）+ 上传材料 →「提交报名」。
3. 「提交状态」按姓名 / 学号查询进度与初筛结果。

## 七、网页版（浏览器直接打开，无需微信环境）

`web/index.html` 是纯静态单文件网页版，**双击即可用**（无需后端、无需构建）。配套 `web/sw.js`（离线缓存，http 访问一次后断网也能打开）与 `web/manifest.webmanifest`（可安装到桌面 / 手机）。

**项目首页（第一个标签）**

- **项目来源**：主办方在「① 招募信息」粘贴公众号链接（自动抓取正文 + `og:image` 封面 + 标题）或导入本地文档 → 解析后点「保存到项目库并展示在首页」。首次打开内置 2 个示例项目。
- **海报**：优先用抓取到的封面图；其次主办方「上传本地海报」（canvas 压缩到 720px / ~0.72 质量后存 dataURL）；都没有则用紫→青渐变占位海报。微信图片有防盗链，加载失败会自动回退到占位海报。
- **截止时间**：从正文里按「截止 / 截至 / deadline + 日期」自动解析（`YYYY年M月D日`、`YYYY-M-D`、`M月D日`），卡片显示剩余天数，≤3 天红色强调，过期置灰。
- **搜索与筛选**：按项目名 / 主办方 / 简介 / 硬条件关键词搜索；筛选「进行中 / 7 天内截止 / 已截止」。
- **详情按钮**：新窗口打开该项目原文链接（公众号文章或官网）。
- **报名按钮**：切换到学生报名页，并按该项目**定制表单**（见下）。

**学生端**

- **一、招募要求与自检**：选定项目后自动显示该项目的硬条件 / 加分项 / 排除项；也可一键上传主办方的需求文件（`.txt` / `.md` / `.docx`）自动解析；填表时实时给出年级、专业、材料的匹配提示（不满足会红字提示）。也可粘贴需求文本。
- **二、智能填表**：上传简历（`.txt` / `.md` / `.docx`）自动识别姓名 / 学号 / 性别 / 年龄 / 年级 / 专业 / 邮箱 / 手机 / 微信 / 技能 / 奖项 / 特长并填表；或点「语音快速填表」口述一段自我介绍自动解析填表；每个输入框右侧 🎤 可单字段语音录入（需 Chrome / Edge）。自动识别出的选项显示为**青色**，方便人工校对。
- **三～七**：基本信息、技能、提升方向、承担工作、材料上传、提交；提交后生成**提交码**（可微信发给主办方）与**报名包 .json**。
- **按项目定制的报名板块**（`buildFormSchema`）：顶部显示项目名称、主办方、截止倒计时与硬/加分/排除项；中部按招募要求**动态生成专属字段**——如要求「每周可投入 8 小时」则生成「每周可投入时长（必填）」、要求「到岗时间」则生成「可到岗时间（必填）」、加分项含作品集/经历/AI 则生成作品集简介、相关经历、AI 工具等字段；材料区按项目标记「必备 / 选交」（排除项里提到某材料不会误判为必备）。必填项未填会阻止提交，缺必备材料会提示。提交时记录 `projectId / projectTitle / projectFields`，导出表「候选人信息总表」含报名项目列。

**主办方端**

- **① 招募信息**：本地文档导入（`.txt` / `.md` / `.docx`），或粘贴公众号链接自动抓取正文（依次尝试公共 CORS 代理；受浏览器同源策略限制失败时，给出「打开 → 复制正文 → 粘贴」的降级指引）。解析出硬条件 / 加分项 / 排除项 / 最少录取人数。
- **②③ 材料导入与筛选**：邮件式归档、作品集解析、五步流水线筛选。
- **推荐原因**：每条结果都给出可读理由——是否满足硬条件 / 命中加分项 n/4 / 作品集优势 / 综合评分 x/49 / 排名与录取线差距（或兜底说明），同步显示在详情页与「初筛结果」导出表。
- **④ 候选人库**：搜索、详情、心仪、一键联系、导出交付物。
- **⑤ 数据同步与离线存储**：见下一小节。
- **导出**：联网时通过 SheetJS 导出单个 xlsx（5 个工作表）；离线自动回退为逐个 CSV 下载。
- 内置 24 位示例申请人，点「载入 24 份示例报名材料」即可体验完整流程（最少录取人数填 12 可看到兜底触发）。

网页版与小程序共用同一套筛选规则（排除项、硬条件、加分项评分、差额驱动的兜底放宽）与作品集规则引擎，结果口径一致。

**手机 / 电脑适配**：≤640px 时项目卡片变为横向滑动（`scroll-snap`）、隐藏轮播箭头、tab 平分宽度；>640px 为自适应网格。首页海报轮播支持手指左右滑动、鼠标拖拽、左右箭头、指示点点击与 5 秒自动播放（滑动后重新计时）。

### 数据存在哪？换设备能不能自动同步？

**结论：不能自动同步。** 页面没有服务器，数据写在打开它的那台设备的浏览器 localStorage 里，按「协议 + 域名 + 端口」隔离。同一台机器换浏览器看不到，清理缓存会丢，学生用自己手机提交的内容不会出现在主办方电脑里。主办方端 ⑤ 面板会实时显示存放位置、已存人数、占用容量、最近保存时间、网络与离线缓存状态，可自行核验。

**离线能做 / 不能做**：填写、保存、筛选、导出 CSV 全程离线可用；首次用 http(s) 打开过一次后，断网也能再打开页面（Service Worker 缓存，双击 `file://` 打开时浏览器会禁用 SW）。导出 xlsx 与公众号抓取需要联网。

**三种汇总方式**（都在 ⑤ 面板里）：

1. **提交码 / 报名包**（推荐，零服务器）：学生提交后复制提交码发微信，主办方「粘贴提交码导入」；或学生发 `.json` 报名包，主办方「导入报名包」可多选批量导入。同名 / 同学号自动合并更新。
2. **分享链接**：`index.html#import=APPL1.xxxx`，打开即导入（链接较长，备选）。
3. **云端接口**（可选）：填一个能存 JSON 的接口地址（如自建或 JSONBin 的公开可写 bin），点「上传 / 拉取」即可多设备共享。注意页面上传时不带鉴权头，需要鉴权的接口请让开发者补请求头。

**回归自检**：`tools/web-smoke.js` 用 jsdom 真实加载网页版并走一遍「招募解析 → 示例材料 → 作品集 → 筛选 → 学生提交 → 提交码导入 → 导出表」，任何运行时错误都会被打印出来。

```bash
npm i jsdom --prefix <你的 node 工作区>
NODE_PATH=<node 工作区>/node_modules node tools/web-smoke.js
```

## 八、本地自测（无需微信云开发）

`tools/local-run.js` 直接复用 `utils/` 与 `cloudfunctions/` 的真实逻辑，造 24 位模拟申请人跑通整条流水线：

```bash
npm i exceljs --prefix <你的 node 工作区>
NODE_PATH=<node 工作区>/node_modules node tools/local-run.js
```

输出：控制台打印归档统计、作品集解析样例、三档结果与兜底记录；`tools/output/` 生成 5 个 xlsx 交付物。
当前基线（minAdmit=12）：24 人 → 推荐 12（含兜底 +7）/ 待定 6 / 淘汰 6（3 人缺作品集 + 3 人年级不符）。

## 九、作品集解析规则（`utils/portfolio.js`）

| 维度 | 规则引擎做法 | LLM 模式 |
| --- | --- | --- |
| 类别 | 12 类关键词词典命中计数，输出「类别 + 组数」，取前 4 | 模型直接归纳 |
| 风格 | 7 类风格词典，取前 2 组合 | 模型直接归纳 |
| 优势 | 8 条规则（叙事 / 落地 / 手绘 / AI / 用户研究 / 策展 / 统筹 / 流程），每条附原文片段 | 模型输出并附证据 |
| 短板 | 4 条「未命中即记为短板」规则 + 类别单一判定 | 模型输出，无则写「无」 |

硬性约束：找不到对应信息一律写「无」，禁止猜测补充；LLM 返回非 JSON 或失败时自动回退规则引擎。

## 十、已知限制（与需求文档待确认事项对应）

- **截图 OCR / 纯图片 PDF 作品集**：内置 `extractPdfText` 仅能抽取未压缩文本流；云函数中若已安装 `pdf-parse` 会优先使用它（可选依赖，未安装自动回退）。更高精度需在云数据库 `config` 配置带视觉能力的 LLM。
- **QQ 邮箱写信页预填**：小程序无法直接拉起邮箱客户端，采用「复制收件人 + 复制全文 + 提示去写信」的最佳实践，真机登录 QQ 邮箱后粘贴发送（最稳妥）。
- **报名表模板字段**：以固定标准《报名申请表》字段映射（已在 UI 展示并可编辑）；如需解析任意 docx/xlsx 模板，可扩展 `parseFormTpl` 接入解析库。
- **最少录取人数 / 兜底优先级**：由招募信息解析生成或人工填写；兜底按「加分项门槛 → 硬条件优先级 → 录取率 25%→30%→35%…」顺序逐步放宽，每轮只补足差额（不再一次性拉满），并标注「兜底入选」。
- **邮件导入**：当前为手动上传 zip 解压归档（1 封邮件 = 1 位申请者，按目录名或文件名前缀归组）；未做邮箱 IMAP 自动收取，如需可接入邮件服务后再扩展 `importMail`。
- 需自备 AppID 并开通云开发环境；云函数部署时选择「云端安装依赖」。
