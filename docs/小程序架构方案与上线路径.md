## 一、先厘清一件事：网页体验版 ≠ 小程序

你希望「在线看到使用效果」，已经给你发布了一个网页体验版：

**https://scfai-screener-demo.app.workbuddy.host/**

但必须说清楚——**这个链接是网页，不是小程序**。

| 事实 | 说明 |
|---|---|
| 小程序不是网页打包 | 小程序是另一套代码：WXML / WXSS / JS + app.json |
| 运行环境不同 | 小程序是双线程架构，**没有 DOM**，`div` / `querySelector` / `addEventListener` 全都不存在 |
| 无法转换 | HTML 不能"编译"成小程序，只能按小程序规范重写 |
| 开发者工具打不开它 | 微信开发者工具只能打开小程序项目，不能打开 HTML 项目 |

**所以这个链接的正确用途是**：当"功能参照物"——你自己、团队、老师打开就能看到完整业务逻辑跑起来是什么样，用来对齐需求和验收。要给别人演示"这将来长这样"，它非常好用。

**但它不能替代小程序交付。**

## 三、架构建议

### 3.1 分包策略（为快速上线）

当前 13 个页面全在主包，142KB 完全够用。但考虑到后续会加海报、吉祥物、更多页面，**建议现在就分包**，避免后期返工。

```
主包（≤ 300KB）
├── pages/entry/          入口页（新，三入口分流）
├── components/pcard/     海报卡片（新，两端共用）
├── components/xc-ball/   吉祥物（新）
├── app.wxss              设计令牌，全站共享
└── utils/                7 个工具模块

分包 A · 学生端  subpackages/student/
  intro · apply · status · detail · receipt        ≈ 60KB

分包 B · 主办方端  subpackages/organizer/
  login · home · recruit · import · portfolio
  candidates · candidate · screen · favorite · contact   ≈ 80KB
```

**为什么这样分：**

| 理由 | 说明 |
|---|---|
| 学生端高频 | 可配 `preloadRule` 进入入口页时预下载，点「学生报名」几乎零等待 |
| 主办方端低频 | 只有老师用，按需加载，不拖累学生端启动 |
| 共用组件留在主包 | `pcard` 两端都用，放分包会导致重复打包 |
| 主包留足余量 | 142KB → 目标 ≤ 300KB，给海报和后续功能留空间 |

**分包配置（app.json）：**

```json
{
  "pages": [
    "pages/entry/entry"
  ],
  "subPackages": [
    {
      "root": "subpackages/student",
      "name": "student",
      "pages": [
        "intro/intro", "apply/apply", "status/status",
        "detail/detail", "receipt/receipt"
      ]
    },
    {
      "root": "subpackages/organizer",
      "name": "organizer",
      "pages": [
        "login/login", "home/home", "recruit/recruit",
        "import/import", "portfolio/portfolio",
        "candidates/candidates", "candidate/candidate",
        "screen/screen", "favorite/favorite", "contact/contact"
      ]
    }
  ],
  "preloadRule": {
    "pages/entry/entry": {
      "network": "all",
      "packages": ["student"]
    }
  },
  "lazyCodeLoading": "requiredComponents"
}
```

### 3.2 tabBar 必须处理（阻塞项）

当前 `app.json` 的 tabBar 挂着两个页面：

```json
"list": [
  { "pagePath": "pages/student/apply/apply", "text": "学生报名" },
  { "pagePath": "pages/organizer/home/home", "text": "主办方" }
]
```

**问题**：tabBar 页面**不能用 `navigateTo` 跳转**，必须用 `switchTab`。加了入口页之后，从入口页点「学生报名」，小程序会直接切到那个 tab、**跳过入口页的视觉设计**，同时底部突然出现导航条，体验割裂。

**两个方案：**

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 去掉全局 `tabBar`，所有页面改普通页 | 学生端少了底部导航；但按单任务拆页原则，本来也不需要 |
| B | 保留 tabBar，入口页用 `redirectTo` | 改动小，但底部导航条会突然出现/消失 |

我建议 A。你的信息架构是"入口分流 → 各自独立流程"，本来就不该有常驻 tabBar。

### 3.3 云环境配置

`config/env.js` 里的 `CLOUD_ENV` 决定连哪个云环境：

```js
// app.js 的逻辑是：留空则自动用默认环境
env: env.CLOUD_ENV || wx.cloud.DYNAMIC_CURRENT_ENV
```

**首次配置步骤**（在微信开发者工具里操作）：

1. 开通云开发，记下环境 ID
2. 填入 `config/env.js` 的 `CLOUD_ENV`
3. **手动创建 5 个数据库集合**：
   `candidates` · `projects` · `favorites` · `contacts` · `notify`
   ⚠️ 云函数不会自动建集合，首次调用找不到集合会直接报错
4. 右键 `cloudfunctions/` 下每个函数 → 「上传并部署：云端安装依赖」

### 3.4 性能红线

| 指标 | 目标 | 当前 |
|---|---|---|
| 主包体积 | ≤ 300KB | ✅ 142KB |
| 首屏启动 | ≤ 1.5s（中端安卓） | 待测 |
| setData 单次载荷 | ≤ 64KB | 待查 |
| 图片 | 走云存储，不进包 | ⚠️ 海报需上传云存储 |

**海报必须走云存储。** 你网页版那 4 张海报 base64 加起来 300KB，塞进主包会吃掉 2 倍余量。正确做法：上传到云存储，用 `fileID` 引用。

### 6.2 已修复：web/ 爆包风险

**问题**：`miniprogramRoot: "./"` 会让整个目录进入打包范围，包括 `web/` 的 11.6MB 资源。

```
修复前：13.16 MB  →  超出主包 2MB 上限 6.6 倍，无法上传
修复后： 0.10 MB  →  余量充足
```

**修复方式**：在 `project.config.json` 加入 `packOptions.ignore`。

```json
"packOptions": {
  "ignore": [
    { "type": "folder", "value": "web" },
    { "type": "folder", "value": "tools" },
    { "type": "file",   "value": "README.md" }
  ],
  "include": []
}
```

| 排除项 | 体积 | 理由 |
|---|---|---|
| `web/` | 11.6 MB | 网页版专用资源（公众号文章缓存 + 海报原图），小程序不需要 |
| `tools/` | 约 36 KB | 本地调试脚本（`local-run.js` / `web-smoke.js`），非小程序代码 |
| `README.md` | 17.9 KB | 项目说明文档，非运行时代码 |

**已验证**：`project.config.json` JSON 语法合法，`ignore` 三项已生效。

⚠️ **`web/` 目录本身不要删** —— 网页版仍在引用它。
