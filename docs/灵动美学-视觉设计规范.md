## 1. 可直接抄的 CSS 变量表

### 1.1 设计前提（决定"耐看 vs 廉价"的三条硬规则）

1. **不用纯黑纯白**：亮色纸感底用 `#F4F1EC` 一类带色相的米灰，文字用 `#2E2A26`；暗色底用 `#141312`（暖中性黑），文字用 `#EDE7DD`。纯 `#000` + `#FFF` 会产生光晕（halation），约 50% 人群有轻度散光，长时间看会糊。
2. **暗色强调色必须重算**：亮色的强调色搬到暗底上会"荧光"。经验值是**提亮 + 降饱和 15–25%**，且暗色模式必须**独立定义变量**，不要复用亮色那套。
3. **暗色靠"表面明度"表达层级，不靠阴影**：暗底上阴影几乎不可见。层级 = canvas → surface → raised → overlay 逐级提亮，配 1px 内高光 `inset 0 1px 0 rgba(255,255,255,.04)`。

### 1.4 主题切换骨架（单文件 HTML 友好，零闪烁）

```css
/* 默认跟随系统；手动切换用 [data-theme] 覆盖 */
@media (prefers-color-scheme: dark){
  :root:not([data-theme="light"]){ /* 把 1.3 的变量块贴这里一份，或用 @import 拆分 */ }
}
```
配套三件事：
- `<meta name="color-scheme" content="light dark">`：让滚动条/表单控件跟随，避免暗色页面出现白色滚动条。
- 在 `<head>` 里放一段**阻塞式内联脚本**读 `localStorage` 并写 `document.documentElement.dataset.theme`，防止刷新白闪（FOUT）。
- 微信/小程序场景：WXSS 支持 `@media (prefers-color-scheme: dark)`（iOS 7.0.12+ / Android 7.0.13+ 客户端），但 `theme` 属性与 `onThemeChange` 事件**必须**在配置里声明 `darkmode: true` 才有。微信内 H5 建议纯 CSS 变量 + 媒体查询，不要依赖 JS 探测。

### 1.5 栅格与留白量级

| 场景 | 栅格 | 外边距 | 列间距 | 内容最大宽 |
|---|---|---|---|---|
| 手机（≤600px） | 4 列 | 16px | 12px | — |
| 平板（600–1024） | 8 列 | 24px | 16px | 720px |
| 桌面（≥1024） | 12 列 | 32px | 24px | 1120px |

留白原则：**同组信息用小间距（4/8）强化绑定，模块之间用大间距（24/32）**。信息密度高的列表行内 padding 用 12/16，不要用 24（会显得松散像后台系统）。

## 2. 字体栈方案（含体积与加载策略）

### 2.1 推荐组合

| 角色 | 字体 | 获取方式 | 实测体积 |
|---|---|---|---|
| 中文正文 | PingFang SC / HarmonyOS Sans SC / Noto Sans SC / Microsoft YaHei | 系统字体栈，**0 字节** | 0 |
| 中文标题·气质字 | Songti SC / Noto Serif SC / Source Han Serif SC | 系统优先；需跨端一致时挂 Google Fonts | 见下 |
| 英文 / 数字 / 时间 | Inter（变体字重）或 Playfair Display（日期大标题） | Google Fonts / rsms.me | latin 子集 woff2 **25.96 KB** |
| 手作感备选 | LXGW WenKai（霞鹜文楷，屏显版） | cn-fontsource npm + jsDelivr | font.css **165 KB**，分片 woff2 约 **38 KB/片** |

### 2.2 中文 webfont 的体积真相（实测数据，别踩坑）

- `https://fonts.googleapis.com/css2?family=Noto+Serif+SC:wght@400&display=swap` → **CSS 本身就 225 KB**，内含 **101 个 `unicode-range` 切片**；单个切片 woff2 约 **2.76 KB**。浏览器只下载页面实际用到的切片，一屏中文通常触发 5–15 片（约 15–45 KB），可控，但**首屏解析 225 KB CSS 是实打实的成本**。
- 极小子集的杀手锏：加 `&text=` 参数。实测 `&text=今日待办已完成`（7 字）→ CSS 仅 **318 字节**，woff2 **3.56 KB**。
  → **用法**：把界面里固定出现的字（标题、星期、月份、"已完成/待办/今日"、数字、标点）做成 `text=` 子集当作"标题字体"；正文一律系统字体。
- 备选 `cn-fontsource-lxgw-wen-kai-gb-screen@1.0.6`（霞鹜文楷屏显版，**OFL-1.1**，可商用）：`font.css` 165 KB，woff2 按 unicode-range 分片，单片约 38 KB。

### 2.3 加载策略

```html
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<!-- 只给标题/数字用：text= 子集，首屏几乎无感 -->
<link rel="stylesheet"
 href="https://fonts.googleapis.com/css2?family=Noto+Serif+SC:wght@600&display=swap&text=今日待办已完成进行中逾期全部一周月年">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400..700&display=swap">
```
- `font-display: swap` 必开；中文字体**禁止** `block`（会长时间空白）。
- 正文永远走系统栈，webfont 只服务"标题 / 日期 / 数字"三处 —— 这是中文项目唯一可持续的方案。
- **微信内打开**：X5/WebView 对外部字体加载不稳定且可能拦截，建议微信场景**只用系统字体栈**（PingFang / HarmonyOS Sans / 系统宋体），零请求、零闪烁。
- 数字统一用 `font-feature-settings:"tnum"`（等宽数字），时间轴/进度数字不会跳动。

### 2.4 一个提醒：Inter 是"AI 味"重灾区

Inter 本身是好字体，但它是 AI 生成 UI 的默认字体，与"靛蓝渐变 + 三卡片"捆绑出现，识别度极高。若想保留 Inter 的易读性又避开套路：只用于**数字与时间**，中文与标题交给宋体系；或改用 Newsreader / Spectral / Playfair Display（衬线）做标题，气质立刻转向"艺术/编辑设计"。

## 3. 组件视觉规范

统一前提：圆角走**梯度化**（小组件大圆角、大容器小圆角），阴影走**双层**（环境软阴影 + 主体承重阴影），阴影色一律取中性暖灰而非 `#000`。

| 组件 | 圆角 | 阴影 | 边框 | 内间距 | 备注 |
|---|---|---|---|---|---|
| **卡片（任务项）** | `--r-md` 12px | 静止 `--sh-1`；hover `--sh-2` | 亮色 `1px solid var(--line-1)`；暗色可省略边框改用表面明度 | 12–16px（移动端 12） | 行高 1.5；标题 16/600，描述 13/400，时间 12/400 `--text-3` |
| **卡片（分组容器）** | `--r-lg` 18px | `--sh-2` | 同上 | 16–24px | 容器越大圆角越克制，别用 24px |
| **Chip / 标签** | `--r-pill`（胶囊）或 `--r-xs` 6px | 无阴影 | 无边框，靠底色与文字色差区分 | `padding: 2px 10px`；高度 22–24px | 字号 12；底色用 `--accent-soft` 一类 10–14% 淡底，文字用压深的同色相 |
| **状态标签（进行中/逾期）** | `--r-xs` 6px | 无 | `1px solid` 同色相 30% | 同上 | 逾期只在文字和 2px 左色条上表达，不要整块红底 |
| **勾选控件** | 外圈 `--r-pill`，内勾线宽 2px | 无 | 未做 `1.5px solid var(--todo-ring)`；已做实心 `--done-ring` + 白色勾 | 触控热区 ≥44×44（视觉 20×20） | 勾选动效 160ms `--ease-out`；勾的路径用 `stroke-dasharray` 描出 |
| **时间轴** | 节点圆点 `--r-pill`，连接线 1px（不用 2px） | 无 | 线色 `--line-1` | 节点直径 8–10px；行间距 24px | 已完成的节点**实心且降饱和**，待办节点**空心**；当前节点用 `--now-accent` + 4px 外晕 `0 0 0 4px rgba(176,130,106,.14)` |
| **日历（月视图）** | 单元格 `--r-sm` 8px | 无 | 今日用 `1px solid var(--now-accent)` | 单元格最小 40×40（移动端 44） | 有任务的日期：日期下方 4×4 圆点（最多 3 个，超出用 "+2"）；选中态用 `--accent-soft` 底而非描边 |
| **热力图（年度）** | 单元 `--r-inner` 4px（**不要用大圆角**） | 无 | 无 | 单元 11×11 + 3px 间隙 | 5 档明度阶梯：0 档 = `--bg-sunken`，1–4 档在 `--accent` 上做 25/45/70/100% 明度；暗色下整体降 20% 亮度 |
| **进度环** | — | 无 | 轨道 3px `--line-1`，进度 3px `--accent`，端点 `round` | 直径 40–56px | 中心数字 14/600 `tnum`；超过 100% 不做满环旋转，做二次细环 |
| **浮层 / 弹窗 / 导航** | `--r-lg` 18px | `--sh-3` | 亮色 `1px solid var(--line-1)` | 20–24px | **唯一允许用玻璃拟态的地方**，且同屏不超过 1 个 |

### 3.1 玻璃拟态（glassmorphism）的正确用法与性能代价

- 成本：每一帧都要把背后的像素复制出来做一次高斯模糊，核复杂度约 O(r²)。实测经验值：中端安卓机上，一张 12px 模糊的玻璃卡可能让 60fps 掉到 40fps，两张到 25fps。全宽导航栏用 blur(24px) 在低端安卓上明显掉帧。
- 硬规则：
  1. 模糊半径 **≤16px**，移动端 `≤8px`（用媒体查询降级）。
  2. **不要嵌套玻璃**（玻璃卡里再放玻璃卡 = 性能翻倍 + 视觉发浑）。
  3. **不要动画 `backdrop-filter`**，入场只动 `opacity` / `transform`。
  4. 同屏 `backdrop-filter` 元素 ≤1–3 个。
  5. 加 `will-change: transform` 与 `contain: layout style paint`。
  6. 必须用 `@supports` 兜底：不支持时给近乎不透明的实色背景（卡片看起来"有意设计"而不是"坏了"）。
  7. Safari 需要 `-webkit-backdrop-filter`（17 以前）。
  8. 尊重 `prefers-reduced-motion: reduce` → 关闭模糊。
  9. 不要让模糊承担可读性：12px 模糊的白底还是白底，文字对比度得自己保证。
- **微信内特别提示**：Android X5 WebView 对 `backdrop-filter` 表现不一致，强烈建议按"默认实色 + `@supports` 升级"实现，移动端直接走实色分支最稳。

## 5. 「已做 vs 待办」状态视觉区分 — 5 种做法对比

| # | 做法 | 具体参数 | 最适用场景 | 代价 / 坑 |
|---|---|---|---|---|
| **A** | **明度反转（下沉 / 浮起）** ★最贴合"光影" | 待办：`--bg-surface` + `--sh-1` + `--text-1`；已完成：`--bg-sunken`（暗一档）+ 去阴影 + `inset 0 1px 0 rgba(255,255,255,.5)` + `--text-2` | 任务列表、卡片流；需要一眼扫出"今天还剩多少" | 亮色下"已完成"变暗容易被误读为不可点，需保证对比度 ≥4.5:1 |
| **B** | **饱和度 / 灰度化** | 已完成：`filter: saturate(.35)` 或直接给降饱和色值（推荐后者，比 filter 更可控）；`opacity: .65` | 已完成的折叠区、归档视图 | `filter` 会连文字一起灰，且触发额外合成层；列表长时掉帧。优先用**两个色值变量**而非 filter |
| **C** | **勾选态（空心 → 实心）** | 未完成：20px 空心圆 `1.5px solid var(--todo-ring)` + 透明底；已完成：实心 `--done-ring` + 白色 2px 勾（160ms `stroke-dasharray` 描出）+ 标题加删除线、字重 600→400 | 任何有复选框的清单，用户心智最强 | 删除线会损伤可读性，长标题慎用；建议只对已完成项用，且与灰度化二选一（别叠满） |
| **D** | **进度环 / 环形进度** | 轨道 3px `--line-1`，进度 3px `--accent`，`stroke-linecap: round`，直径 40–56px，中心 `tnum` 数字 | "今日完成度""周目标"这类**聚合指标**，不用于单条任务 | 单条任务用进度环是噪音；>100% 需要第二段细环，否则视觉撒谎 |
| **E** | **留白 / 空间让位**（差异化布局） | 已完成项：缩小行高（56→44px）、去掉描述行、左侧 2px 色条降为 1px、整组折叠为"已完成 3 项" | 长列表、日历日视图；配合 A 使用效果最好 | 高度变化会引发列表跳动，需 `transition` 或先折叠再动画 |
| 补充 | **左色条 / 项目色** | 卡片左侧 2–3px 竖条，取低饱和项目色 | 多项目并行时区分"属于哪条线" | 色条颜色不得超过 4–5 种，否则变成廉价彩虹 |

**组合建议（本项目）**：**A（明度反转）为骨架 + C（勾选态）为交互 + D（进度环）做日/周聚合**，B 只用于"已完成"折叠区，E 用于长列表。三套以内，超过就是过度设计。
**可访问性底线**：任何"弱化已完成"的处理，正文对比度不得低于 **4.5:1**（大字号 3:1）；不要用"仅靠颜色"区分，必须同时有形（勾/删除线/位置）或文字差异。

### 6.2 值得读的中文 / 中文团队规范

- **TDesign（腾讯）Design Token 文档**：`tdesign.tencent.com` — 给出可直接抄的圆角/阴影/字体 token 命名与取值，例如 `--td-shadow-1: 0 1px 10px rgba(0,0,0,5%), 0 4px 5px rgba(0,0,0,8%), 0 2px 4px -1px rgba(0,0,0,12%)`（三层叠加阴影），中圆角 `--td-radius-*`，另有小程序深色模式方案（`prefers-color-scheme` + `page,.page` 双选择器）。
- **Semi Design（字节）Token**：圆角梯度 `3 / 3 / 6 / 12 / 9999px`；暗色阴影范式很有参考价值 —— `inset 0 0 0 1px rgba(255,255,255,.1), 0 4px 14px rgba(0,0,0,.25)`，即**暗色用 inset 描边 + 弱投影**勾勒层级。
- **Arco Design（字节）Token**：圆角 `2 / 4 / 8px` 三级；阴影 `0 0 5/10/20px rgba(0,0,0,.1)` 三档。
- **微信深色模式设计原则**（掘金等平台有中文拆解）：不用纯黑、暗色下强调色降饱和、用负空间减重、分割线在暗色下几乎不可见 —— 这套原则与"克制、高级感"目标完全一致，且直接适用于微信内打开的场景。

### 6.3 从案例中提炼的视觉特征（只学方法）

- **"精准模糊"**：模糊只用在卡片/按钮等小组件，5–10px，不再全屏铺。
- **AI 图像的节制用法**：作为背景辅助而非视觉焦点，通过**降饱和 + 叠加纹理 + 缩小占比**规避塑料感 —— 这条对"艺术类工具"尤其受用。
- **单主色 + 黑白灰**：85% 的高质感案例是"一个主色 + 中性色"，靠明度与饱和度造层次，而不是堆配色。
- **低饱和 ≠ 灰暗**：廉价感来自"对比度塌掉 + 缺少强调色"，不是来自饱和度高。低饱和底 + 一个满饱和的行动按钮，反而让 CTA 更跳。

## 7. 反面清单（一眼廉价 / 一眼 AI 生成）

### 7.1 配色与渐变

- ❌ **靛蓝→紫色渐变**（`#6366F1 → #A855F7`）。源头是 Tailwind UI 当年把按钮默认设成 `bg-indigo-500`，被模型学成"按钮就该是紫色"，已成 AI 生成 UI 的指纹。
- ❌ **渐变按钮 / 渐变文字**（左上→右下的亮蓝紫 + 白字）。
- ❌ **暗底 + 高饱和强调色**：在深色背景上会产生视觉振动（vibration），必须降饱和。
- ❌ **每个模块一个背景色**（三张卡片三种浅色底）或"不同颜色左边框"做分区 —— 这是最典型的偷懒分区法。
- ❌ 纯 `#000` 背景 + 纯 `#FFF` 文字；纯黑实线分割线（应改用 `#E2DCD3` 一类的发丝线）。

### 7.2 形状、阴影与材质

- ❌ **全站统一大圆角**（16 / 20 / 24px），尤其大容器也用大圆角。正确做法是梯度化：小组件胶囊、卡片 12px、大容器 4–6px。
- ❌ **弥散重阴影** `box-shadow: 0 10px 40px rgba(0,0,0,.2)` 到处撒；或所有元素阴影参数一模一样。
- ❌ **玻璃拟态滥用**：全屏毛玻璃、玻璃卡套玻璃卡、模糊半径 24–30px、给 `backdrop-filter` 做动画。
- ❌ 阴影色一律 `rgba(0,0,0,...)` —— 应从页面中性灰里取色降明度，阴影才会"融进"色调。

### 7.3 字体与图标

- ❌ **Inter / system-ui 默认参数直接用**，不加字距、字重、字号体系调整。
- ❌ **emoji 当图标**（✨ 🚀 🔒 ✅ 一排三）—— 跨平台渲染不一致，且是最强的"廉价信号"。
- ❌ 图标风格混用（线性 + 填充 + 两个库混着来）。
- ❌ 每个图标都配文字标签；页面顶部还要加个大标题"我的待办事项列表" —— 把一眼能懂的东西再说一遍，是 AI 文案的典型病。

### 7.4 结构与文案

- ❌ **万能骨架**：Hero 大字 → 一句模糊副标题 → **三张并排图标卡片** → 居中 CTA。这是 AI 的统计中心，看到就等于"没想法"。
- ❌ 过度描述：一句话能说清的写三段；按钮文案含糊（"开始使用"）。
- ❌ CTA 对比度不足（约 2.5:1）—— 技术上"有"，实际上看不见。
- ❌ 效果做加法：能加的动效全加，缺少克制。**好的设计是做减法**。

### 7.5 本项目专属禁忌

- ❌ 在微信内首屏挂外链中文 webfont（慢 + 可能被拦 + 白闪）。
- ❌ 桌面端 283–549 KB 的日历/时间轴库塞进手机首屏。
- ❌ 用 JS 检测主题导致刷新白闪（应在 `<head>` 内联阻塞脚本写 `data-theme`）。
- ❌ 移动端用 blur > 8px 的毛玻璃导航。
