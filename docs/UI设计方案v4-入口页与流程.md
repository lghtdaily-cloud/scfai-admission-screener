## 一、入口页（新的小程序首屏）

### 1.1 页面结构

```
┌─────────────────────────┐
│                         │
│        （跳跃圆球）        │   占屏高约 34%
│                         │
│      川美课题招募          │
│   选好项目，我帮你把表填完     │
│                         │
├─────────────────────────┤
│  ▌进入首页                │   ← 深色实底（主推）
│    浏览正在招募的项目        │
├─────────────────────────┤
│    学生报名平台            │   ← 白色描边
│    填表、上传材料、查进度     │
├─────────────────────────┤
│    主办方端                │   ← 白色描边
│    导入报名、AI 筛选候选人   │
├─────────────────────────┤
│   四川美术学院 · 课题招募     │
└─────────────────────────┘
```

### 1.2 三处设计决策

**① 只推一个主按钮。**
"进入首页"用深色实底（`#14131A` 底 + 米白字），另两个用白色描边卡。
理由：首屏只能有一个视觉重心。三个按钮一样重，用户反而不知道点哪个。

**② 圆球在首屏做跳跃动画。**
入口页是唯一允许吉祥物持续动的地方（其他地方它只短暂出现）。圆球做 480ms 上下跳 + 3~6 秒随机眨眼 + 轻微左右晃，落地时压扁一下。

**③ 三个入口各自独立，不共用 tabBar。**
学生和主办方是两套完全不同的功能，混在一个 tabBar 里会互相干扰。

### 1.3 页面归属

| 入口 | 目标页面 | 现有文件 |
|---|---|---|
| 进入首页 | 项目浏览 | `pages/student/intro/`（改造） |
| 学生报名平台 | 学生报名 | `pages/student/apply/` |
| 主办方端 | 主办方工作台 | `pages/organizer/home/` |

⚠️ **技术注意**：现有 `app.json` 的 tabBar 包含 `student/apply` 和 `organizer/home`。
入口页若作为首页，tabBar 页面无法用 `navigateTo` 跳转（tab 页必须用 `switchTab`）。
**两种处理方式**：
- **方式 A（推荐）**：去掉全局 tabBar，全部改为普通页面用 `navigateTo`。入口页回归即可换角色。
- **方式 B**：保留 tabBar，入口页做成 `redirectTo` 跳到 tab 页。但这样用户回不到入口页。

## 二、三条功能链路

### 2.1 链路一 · 首页浏览（向所有人开放）

```
入口页
  → 首页（项目海报轮播）
      · 横向滑动切换项目
      · 点击海报 → 灰化 + 显示信息
  → 项目详情（只读）
      · 招募要求 / 截止时间 / 需要准备什么
  → 开始报名
      · 跳转到学生报名平台（带项目 ID）
  → 提交回执
      · 提交码
```

### 2.2 链路二 · 学生报名平台

```
入口页 → 学生端
  → 选项目（若从首页带 ID 进入则跳过）
  → 智能填表
      · 基本信息（可从简历自动回填）
      · 作品集上传
      · 个人陈述
      · 底部固定「提交」
  → 提交回执（提交码）
  → 报名进度（三节点时间轴）
  → 结果页（录取 / 待定 / 未选）
  → 联系老师（录取后出现）
```

### 2.3 链路三 · 主办方端

```
入口页 → 主办方端
  → ① 使用教程屏（三步说明）
      · 选择项目 / 导入学生信息 / AI 一键筛选
      · 底部「开始 · 选择项目」
  → ② 选择项目屏
      · 列出各课题，显示已收报名数
      · 单选，选中项加粗边框 + 勾选标记
      · 底部「确定 · 进入导入」
  → ③ 导入与筛选屏
      · 两个指标：已导入 / 已推荐
      · 「导入报名邮件」卡（.eml / ZIP）
      · 「AI 一键筛选」深色主卡
      · 底部「查看候选人库」
  → 候选人列表（按分排序）
  → 候选人详情（七维评分）
```

**主办方端的关键顺序：先选项目，再导入，最后筛选。**
这个顺序不能颠倒 —— 导入的数据必须归属到某个课题，筛选也是按课题筛选。
